# anitech-performance — сборный репозиторий лабораторных

Личная учебная программа пользователя: Laravel/PHP-разработчик (~1.5 года), закрывает пробелы в ООП, инфраструктуре, БД и заодно смотрит фронтенд. Общение — на русском.

## Устройство репозитория

- Родитель: `meeymirita/anitech-performance` (раньше назывался `submodule-group-lab`). Сайт — GitHub Pages на `anitech.meeymirita.ru` (`CNAME`).
- Файлы самого сайта в корне: `index.html` (главная, карточки лаб, маршруты), `changelog.html`, `favicon.svg`, `docs/screenshots/` (скриншоты для модалки «О проекте»).
- Каждая папка ниже — **git-подмодуль** со своим репозиторием `meeymirita/<тема>-lab`:

| Папка | Репозиторий | Что |
|---|---|---|
| `docker` | docker-lab | Docker + Bash |
| `php-coffee` | **oop-lab** (имя не совпадает!) | ООП на PHP — Coffee Shop API |
| `php` | php-lab | Чистый PHP: роутер, DI, PDO, CSRF |
| `traefik` | traefik-lab | reverse proxy, TLS |
| `kubernetes` | kubernetes-lab | от Compose к k8s |

| `js` | js-lab | Чистый JS (это лаба, а не скрипты сайта) |
| `vue` / `typescript` / `nuxt` | vue-lab / typescript-lab / nuxt-lab | фронтенд |

В каждой лабе: методичка HTML (например `php-coffee/docs/OOP_Lab_CoffeeShop.html`), README со строкой «Статус:», код прохождения пользователя.

**Актуальный статус лаб — строки «Статус:» в корневом `README.md` и README каждой лабы.** Читать их, а не полагаться на память.

## Правила git

1. **Сначала пушить подмодуль, потом родителя.** Если родитель ссылается на коммит подмодуля, которого нет на GitHub, сборка Pages падает на checkout (`not our ref …`). Так было 26.09 с `works`.
2. Перед пушем родителя проверить, что ни один подмодуль не опережает свой origin:
   `git submodule foreach --quiet 'b=$(git rev-list --count @{u}..HEAD 2>/dev/null); [ "${b:-0}" != 0 ] && echo "$name ahead $b"; true'`
3. Порядок коммитов: коммит в подмодуле → отдельный коммит в родителе «Bump <лаба> submodule: …».
4. Коммитить и пушить только по просьбе пользователя. Сообщения коммитов — на английском.
5. Оболочка может стоять внутри подмодуля. Проверять `pwd` перед `cd <папка>`.

## Интеграция новой / обновлённой лабы

README лабы; строка в таблице и нумерованный раздел корневого `README.md`; карточка в `index.html`; `works/<key>.html` + запись в `LABS` (иначе карточка ведёт на 404); `changelog.html` (карта LABS + запись за день); `fixes/_order.md` и `fixes/_proofread.md`. Папку `<name>-sources/` (служебные файлы сборки из чата) удалять.

Уровень сложности («Базовая/Средняя/Высокая») не выводить из содержания — брать тот, что задал пользователь, иначе спросить.

Частая ошибка в методичках: в ссылках на другие лабы путают «раздел N» (теория) и «сессия N» (практика). При вычитке сверять с настоящей нумерацией.

## Как вести пользователя по лабе

- Сначала пользователь пробует сам, потом разбираем («напиши как понял — поправлю»). Не вываливать длинную теорию заранее.
- Показывать поведение, запуская код в контейнере лабы (`var_dump`, специально сломанные примеры), а не только объяснять словами.
- На «сложно / непонятно» — не добавлять деталей, а упростить: аналогия, короткая карта файла, попросить показать, что именно непонятно.
- Любое утверждение о коде проверять запуском, прежде чем выдавать как факт.
- Ответы короткие и конкретные. Не пересказывать уже пройденное.
