### Часть 1 (разделы 1–9, до шага 1.4 включительно)

- **[тех] Шаг 1.1, docker-compose.yml, комментарий про RabbitMQ-пользователя** — комментарий гласит: «# load_definitions (rabbitmq.conf) — пользователя cafe/cafe создаёт только # блок "users"/"permissions" в definitions.json ниже. Без него — Not_Authorized...», но показанный чуть выше в том же шаге код `rabbitmq/definitions.json` содержит только `vhosts`, `exchanges`, `queues`, `bindings` — блоков `"users"`/`"permissions"` в нём нет. Получается, методичка сама описывает необходимость этого блока, но не приводит его в коде: следуя шагу 1.1 буквально, пользователь cafe/cafe в RabbitMQ не будет создан, вход в UI (`http://localhost:15672`, cafe/cafe), заявленный в «ожидаемом результате» этого же шага, закончится Not_Authorized. (Для сравнения: в реальном репозитории `/home/user/submodule-group-lab/php-coffee/rabbitmq/definitions.json` такой блок `"users"/"permissions"` присутствует — значит, кто-то добавил его вручную сверх того, что описано в методичке.) Исправление: добавить в пример `definitions.json` шага 1.1 блоки `"users": [{"name":"cafe","password":"cafe","tags":["administrator"]}]` и `"permissions": [{"user":"cafe","vhost":"/","configure":".*","write":".*","read":".*"}]`.

- **[тех] Шаг 1.2, эксперимент (в) «количество: qty => -2»** — заявленный «ожидаемый результат»: «Итого: 150 ₽ ← −920 + 150; тоже молча». Арифметика в самой подсказке не сходится: −920 + 150 = −770, а не 150. Реальный запуск кода методички (itemPrice/orderTotal с латте L, extras oat+shot, qty=-2, плюс эспрессо S, qty=1) подтверждает: `php lab0/01_arrays.php` с этими данными печатает «Итого: -770 ₽», а не «Итого: 150 ₽». Исправление: заменить заявленный вывод на «Итого: -770 ₽ ← −920 + 150».

- **[противоречие] Раздел 1, вводная таблица «пять вопросов»** — строка «Оплатить заказ: наличные, карта, бонусы» описывает решение как «три класса, реализующих PaymentMethod; в тесте подставляем четвёртый, поддельный». Однако по структуре проекта (раздел 7: `Payment/ PaymentMethod + CashPayment, CardPayment; CardGateway (interface); PaymentType; Receipt; PaymentFailed`) в основной лабе строится только два класса — `CashPayment` и `CardPayment`. `PaymentType::Bonus` и `BonusPayment` упоминаются лишь один раз во всём документе — как необязательное самостоятельное упражнение «Сделайте сами» в шаге 4.3, а не как часть демонстрируемого решения. Заявление «три класса» во вводном примере вводит в заблуждение относительно того, что реально строится по шагам. Исправление: либо изменить пример на «наличные, карта» (два класса), либо явно пометить бонусы как задание «сделайте сами» уже во вводной таблице.
