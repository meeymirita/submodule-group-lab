# Kubernetes Lab — находки

Методичка: `kubernetes/Kubernetes_Lab_Plan.html`. Битых якорей в оглавлении нет.

## 🟢 Что хорошо
- apiVersion'ы актуальные: `apps/v1`, `autoscaling/v2` (HPA), `traefik.io/v1alpha1` (новая группа CRD Traefik v3,
  не устаревшая `traefik.containo.us`), `kind.x-k8s.io/v1alpha4`.
- README честно пишет «нужны пройденные Docker Lab и Traefik Lab».

## 🟡 Жёсткая зависимость от кода Traefik-лабы
Шаг 1.4: «Каталог api/ с Dockerfile и server.js — тот же самый, что вы собрали в Traefik-лабе… Скопируйте его»,
образ `traefik-lab-api:v1`. То есть без **пройденной** (а не просто прочитанной) Traefik-лабы шаги не выполнить.
Стоит сказать это в самом начале методички (блок «перед стартом»): «понадобится папка `api/` из Traefik-лабы».
Хорошо бы дать запасной вариант (ссылку на готовый `api/` в репозитории traefik-lab), если Traefik-лабу
проходили давно или не до конца.

## 🟡 Версии не указаны
Ни в README, ни в карточке, ни в методичке нет версии Kubernetes / kind. Это важно: `kind` по умолчанию берёт
образ узла своей версии, и через год поведение (например, HPA/metrics-server) может отличаться.
Предложение: в шаге 1.1 зафиксировать образ узла (`kind create cluster --image kindest/node:v1.3x.x`) и
написать в стеке «проверено на kind 0.2x / Kubernetes 1.3x».

## 🟡 Мелкие несостыковки с Traefik-лабой
- Traefik-лаба: `postgres:16`, здесь — `postgres:16-alpine`. Не ошибка, но раз смысл лабы «переносим тот же стек»,
  лучше взять тот же тег (или пояснить, зачем alpine).
- Traefik закреплён на `v3.1` в обеих лабах — консистентно. Актуальная ветка v3 уже новее (3.5+); на v3.1 всё работает,
  но при обновлении обеих лаб — обновлять вместе.

## Метрики
Для HPA нужен metrics-server (упоминается 11 раз). В kind он обычно требует флаг `--kubelet-insecure-tls` —
проверь, что этот флаг есть в шаге установки (автоматической проверкой не определить, глазами — 1 минута).
