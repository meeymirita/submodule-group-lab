# Traefik Lab — находки

Методичка: `traefik/Docker_and_Traefik_Lab_Plan.html`. Битых якорей в оглавлении нет.
README, карточка и методичка согласованы: Traefik 3, Docker Compose, Node.js API, PostgreSQL, Adminer.

## 🟢 Синтаксис Traefik v3 — корректный
Проверил типичные ловушки миграции v2 → v3: нет `ipWhiteList` (в v3 — `ipAllowList`), нет старого синтаксиса
`HostRegexp(`{...}`)`, нет удалённого `swarmMode`, нет старой группы CRD `traefik.containo.us`. Образ закреплён: `traefik:v3.1`.
Упоминание «Traefik 2» — только в историческом контексте.

## 🟡 На эту лабу жёстко опирается Kubernetes
Kubernetes-лаба копирует отсюда `api/` (Dockerfile + server.js) и собирает образ `traefik-lab-api:v1`.
Значит, при правках API здесь нужно проверять шаги 1.4+ в Kubernetes-лабе. Имеет смысл добавить в конец
этой методички строчку «Не удаляй папку `api/` — она понадобится в Kubernetes Lab».

## 📖 Вычитка методички

### Часть 1 (разделы 0–7)
- **[текст] Раздел 6 «Сценарий: путь запроса», раздел 7 (таблица Middlewares)** — в HTML-источнике буквально `<code>Host(\`api.localhost\`)</code>` и `<code>PathPrefix(\`/app\`)</code>` (лишний обратный слэш перед каждым бэктиком) → в браузере вместо `Host(`api.localhost`)` читатель видит `Host(\`api.localhost\`)` с видимыми слэшами → убрать экранирующие `\` перед бэктиками (как это верно сделано в блоке `<pre>` раздела 5 с примером whoami).
- **[противоречие] Раздел 1 «Разбор задачи», таблица «Что доработано», строка «Один Docker provider на всё»** — «раздел 5 объясняет providers и когда нужен file provider вместо labels» (ссылка `href="#sec-5"`) → объяснение двух видов providers (Docker vs file) и их merge на самом деле находится в разделе 2, в блоке «🔬 Под капотом: почему providers два вида»; раздел 5 («Service Discovery через labels») про file provider вообще не говорит, только про Docker-labels на примере whoami → исправить ссылку на раздел 2 (`#sec-2`).
- **[противоречие] Раздел 0.5 «Сеть», врезка «ЭТО КЛЮЧЕВАЯ ИДЕЯ ДЛЯ ВСЕЙ ЛАБЫ»** — «когда в разделе 5 вы увидите `traefik.http.services.api.loadbalancer.server.port=3000`» (ссылка `#sec-5`) → в разделе 5 показан только пример `whoami` с `port=80`; label `api` с `port=3000` появляется только в шаге 2.1 (Сессия 2), которого на момент раздела 5 в тексте ещё не было → сослаться на шаг 2.1, а не на раздел 5.
- **[противоречие] Раздел 3 «Итоговая архитектура», абзац после ASCII-диаграммы** — «PostgreSQL и API дополнительно используют внутреннюю сеть `backend`, недоступную из `traefik-public` — Traefik физически не может замаршрутизировать трафик напрямую в БД, только через API или Adminer» → если в сети `backend` по тексту только `PostgreSQL` и `api`, то `adminer` до БД достучаться не может вообще, а фраза тут же утверждает обратное («через API или Adminer»); по факту (см. шаг 2.3, сервис adminer) `adminer` тоже подключён к `traefik-public` и `backend` → добавить `adminer` в перечисление сервисов сети `backend`.
- — остальное в разделах 0–7 проверено, расхождений не найдено: соответствие оглавления (сайдбар и «Содержание») заголовкам `id="sec-0"`…`id="sec-8"` и их порядок; последовательность сносок-глоссария 1–10 (Traefik, TLS, статическая/динамическая конфигурация, EntryPoint, Provider, Router, Middleware, Service, round robin) без пропусков и дублей; перекрёстные ссылки «шаг N.N» на шаги 1.2, 1.3, 1.5, 1.6, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2 — совпадают с оглавлением сессий; команды `docker pull/build/run/ps/logs/exec/stop/rm` и `docker compose up/ps/logs/down` (блоки 1–2 pre_blocks.txt) — синтаксис и комментарии верны; ASCII-диаграммы разделов 2 и 3 (блоки 3–4) и дерево каталогов раздела 4 (блок 5) внутренне согласованы (imена сетей `traefik-public`/`backend`, сервисов, портов 80/443) с кодом более поздних шагов (2.1, 2.3, session 3); пример label whoami (блок 6, раздел 5) — синтаксис Traefik v3 корректен (`Host(...)` с бэктиками, `entrypoints=web`, нет устаревшего v2-синтаксиса); латиница вместо кириллицы в прозе разделов 0–7 не найдена (проверено скриптом по символьным паттернам); сырые бэктики вне `<code>`/`<pre>` в разделах 0–7 не найдены.
